# Astyle 批量风格化工具 — 需求说明书

- 日期：2026-11-02
- 状态：**已实现**（tkinter 实现，纯 Python 标准库，无第三方依赖）
- 形态：本机自用 Windows 桌面小工具，共 2 个 Python 文件

---

## 1. 背景与目标

现状：在 Source Insight 中对**单个文件**执行脚本

```
"D:\astyle\astyle.exe" --options="D:\astyle\.astylerc" %f
```

目标：做一个 GUI，把"单文件"扩展成"整目录批量"，**格式化效果与上面那条命令完全一致**（同一个 exe、同一份 `.astylerc`、不额外施加风格参数），并能逐文件看到处理结果。

---

## 2. 环境与关键结论（已实测验证）

| 项目 | 说明 |
|---|---|
| Python | 3.10.11 |
| GUI 库 | Python 内置 `tkinter`（Tk 8.6），**无需安装第三方包** |
| astyle | Artistic Style **3.6.20**，随程序附带于 `<程序目录>\astyle\astyle.exe` |
| 配置文件 | `<程序目录>\.astylerc`，程序启动时的默认风格配置 |

### 2.1 实测发现的 4 个关键事实（直接影响实现）

| # | 事实 | 影响 |
|---|---|---|
| R1 | `.astylerc` 里含有 `--quiet`，**astyle 对文件不输出任何文字**（实测加 `-v -Q` 也压不住 `--quiet`） | **不能靠解析 astyle 输出判断"已格式化/无变化"**。改用"格式化前后文件内容哈希对比"判定，100% 可靠 |
| R2 | `.astylerc` 里含有 `--suffix=none`，且实测命令行追加 `--suffix=.orig` **无效**（不会生成 .orig） | 备份功能**由程序自己实现**（复制一份 `<文件名>.orig`），与 astyle 参数解耦 |
| R3 | 单文件成功格式化的退出码为 `0`；本工具参数里**不需要** `--recursive`（逐文件调用） | 退出码非 0 即可判为失败，再叠加哈希判定区分"已改/未改" |
| R4 | `.astylerc` 含 `--mode=c`、`--lineend=windows`、`--style=allman` 等全部风格项 | 程序**只追加** `--options=<rc>` 和 `--suffix=none` 这两个开关，保证风格与 Source Insight 完全一致 |

> 结论：判定逻辑与备份逻辑都必须由 Python 自己完成，不能依赖 astyle 的输出文本和 `--suffix`。

## 3. 已确认的决策

| 编号 | 决策 |
|---|---|
| Q1 | 默认**递归**子目录，界面可取消 |

| 开始风格化 | ttk.Button | 见 4.3 流程；运行中禁用 |
| 停止 | ttk.Button | 运行中才可用；**不杀进程**，处理完当前文件后停止，日志写"已请求停止，将在当前文件处理完成后中止" |

### 4.3 执行流程

```
[开始风格化] → 校验 → 扫描文件 → 确认 → 逐文件处理 → 汇总 → 收尾
```

1. **校验**（任一失败则弹窗提示并中止，不进入扫描）
   - exe 路径非空、文件存在且扩展名为 `.exe`
   - rc 路径非空且文件存在
   - 代码目录非空且是已存在目录
   - 至少勾选一种扩展名
2. **扫描**（主线程内快速完成；文件系统异常弹窗提示并中止）
   - 递归开关决定是否进入子目录；按勾选扩展名过滤
   - 跳过"排除目录"命中的整棵子树
   - 结果按路径字符串升序排列，保证日志顺序稳定
   - 扫描到 0 个文件 → 提示"没有找到可处理的文件"，中止
3. **确认**（仅实际模式，非预览）
   - 弹确认框：标题 `确认风格化`，正文 `将对 N 个文件执行风格化。` + 目录、递归与备份状态 + `说明：只调整代码的缩进、空格与换行，不删除文件、不涉及硬盘格式化。`（预览模式不弹，直接跑）
4. **逐文件处理**（后台 `threading.Thread`（daemon）+ `queue.Queue` 事件，串行；主线程 `after(60ms)` 轮询取事件）
   - **预览模式**：把文件复制到 `%TEMP%\astyle_preview_<随机>\`，对副本执行 astyle，比较复制前后副本内容哈希 → 输出 `将会修改` / `无需修改`，结束后删除临时目录。**原件字节零改动**。
   - **实际模式**：
     a. 若勾选备份 → 复制 `<file>` 为 `<file>.orig`（已存在则直接覆盖，`.orig` 始终等于本次格式化前的内容）
     b. 读入原文件字节 → `sha256`
     c. `subprocess.run([exe, "--options=" + rc, "--suffix=none", file], shell=False, capture_output=True, timeout=60)`
     d. 再读字节 → `sha256`；两次不同 → `OK/已格式化`；相同 → `SKIP/无变化`，且**删除刚生成的 `.orig`**（删除失败记 `无变化（备份删除失败：原因）`，仍按 SKIP 计数）
     e. 退出码非 0 → `FAIL`，附"退出码 N"及 astyle 输出片段；输出被 `--quiet` 抑制时补充提示"可能是文件只读或被占用"
   - 单个文件处理中出现未预期异常时按 `FAIL` 记录并继续，**绝不中断整批，也绝不遗漏"完成"汇总**
   - 每处理完一个文件立刻投递事件刷新一行日志与进度
   - 每个文件处理前检查一次停止标志（协作式中止，`threading.Event`）
5. **汇总**：状态栏 + 日志末行 `完成：共 N，已格式化 A，无变化 B，失败 C，用时 T s`（中途停止则头部为"已停止"）
   - 实际模式且 C>0 → 弹窗 `有 C 个文件处理失败，共处理 N 个文件。详见日志。`
   - 预览模式 → 弹窗 `A 个文件将会被修改，B 个无需修改。原文件未被改动。`
6. **收尾**：恢复按钮可用状态；工作线程引用置空；日志文件句柄关闭。

### 4.4 日志规范

- 界面：`tk.Text`（`state="disabled"` 只读、`wrap="none"`、`Consolas 10pt`、双向滚动条），插入后 `see("end")` 自动滚动到底，支持选中复制；超过 5000 行时自动从头部批量裁剪（文件日志不受影响）。
- 单行格式：`[HH:MM:SS] [STATUS] <相对路径>  <说明>  <耗时s>`
  - 路径显示**相对代码目录**的路径，避免超长。
  - STATUS 与配色：`OK` 绿、`SKIP` 灰、`FAIL` 红、`INFO` 默认色；用 `Text.tag_configure(<level>, foreground=...)` 预定义标签，插入行时带对应标签。
- 日志文件：`<程序所在目录>\logs\astyle_YYYYMMDD_HHMMSS.log`，**UTF-8 带 BOM**（Windows 记事本友好），内容与界面完全一致（纯文本，无颜色）。目录不存在时自动创建；同一秒内重复开始时依次追加 `_2`、`_3` 后缀，不覆盖上一次日志。
- 失败行同时写 astyle 的 stderr/stdout 原文（单行化，最多 300 字符；若为空则只写退出码并附常见原因提示）。

### 4.5 异常与边界处理

| 场景 | 处理 |
|---|---|
| astyle 路径不存在 / 不是 .exe | 开始前弹窗拦截；"刷新"按钮提示无法执行/检测失败 |
| rc 路径不存在 | 弹窗拦截（不提供"仅用默认风格继续"，避免和 SI 效果不一致） |
| 目录无权限 / 文件被占用（返回非 0） | 记 FAIL 继续，不中断整批 |
| 文件是只读属性 | astyle 会报错 → FAIL，日志提示"可能是文件只读或被占用" |
| 路径含中文/空格/`&` | 全程 `subprocess` 参数列表 + `Path`，禁用 shell 拼接 |
| astyle 卡死 | 单文件超时 60s（`subprocess.run(timeout=60)`），超时 → FAIL("执行超时")；无法启动进程 → FAIL("无法启动 astyle") |
| 用户在运行中关闭窗口 | `protocol("WM_DELETE_WINDOW", ...)` 弹确认：`文件正在处理中，确定中止并退出吗？` → 置停止标志，状态栏提示"等待当前文件结束后退出"，等当前文件结束后保存设置并退出（`join(3.0)`） |
| 运行中重复点开始 | 按钮已禁用，控制器内亦有运行态判断，不会重入 |
| `.orig` 已存在 | 直接覆盖为本次格式化前的内容；若本次格式化无变化，则删除该 `.orig`（避免堆积与源文件相同的备份） |

## 6. 技术方案要点

| 关注点 | 方案 |
|---|---|
| 进程调用 | `subprocess.run(argv_list, shell=False, capture_output=True, timeout=60, creationflags=CREATE_NO_WINDOW)` |
| 命令行构造 | `[exe, f"--options={rc}", "--suffix=none", file]`；**不加**任何风格类参数 |
| 异步 | `threading.Thread`（daemon）跑 `FormatWorker`，只往 `queue.Queue` 投事件；主线程 `after(60ms)` 轮询刷新界面；停止用 `threading.Event` 协作式中止；`done` 事件在 `finally` 中投递，保证汇总必达 |
| 容错 | 单文件处理兜底 `Exception` 按 FAIL 记录并继续；扫描阶段 `OSError` 弹窗中止 |
| 编码 | 捕获 bytes → 先 `utf-8` 再 `gbk` 回退（中文 Windows 报错常为 GBK） |
| 结果判定 | 前后 `sha256` 对比（见 R1），失败看退出码 |
| 备份 | Python `shutil.copy2` 生成 `.orig`（见 R2），无变化时删除 |
| 预览 | 复制到临时目录实际格式化后对比（astyle 输出被 quiet 抑制，`--dry-run` 不使用） |
| 设置持久化 | `configparser`（`interpolation=None`）读写 `settings.ini` 的 `[General]` 段，与 `main.py` 同目录，UTF-8 明文 |
| 排除匹配 | 目录名统一 `normcase` 后比较：纯名字按层级匹配，含分隔符按路径前缀匹配 |
| 单实例 | 不做，允许多开（风险低，自用） |
| 打包 | PyInstaller 目录模式（`--windowed`，无控制台窗口）；打包后 `APP_DIR` 取 exe 所在目录，`.astylerc`、`astyle\`、`settings.ini`、`logs\` 均落在发布目录，详见 `docs/打包说明.md` |
| 日志性能 | 每行 `Text.insert("end", line, tag)` + `see("end")` 一次，插入时临时 `state="normal"`、写完复位 `disabled`；文件句柄常开 `flush()`；界面超 5000 行自动裁剪头部 |

## 7. 明确不做（范围外）

- 不做风格规则编辑器（`.astylerc` 只读查看，编辑仍在外部）。
- 不做 Source Insight 集成/插件。
- 不做格式化前后 diff 预览。
- 不做多目录批量、不做多进程并发、不做按 mtime 过滤。
- 不做"一键还原 .orig"。
- 打包发布采用 PyInstaller **目录模式**（`--windowed`，无控制台窗口，见 `docs/打包说明.md`）；不做单文件 exe 与安装程序。
- 不做深色主题/皮肤。
- 不做文件拖放（tkinter 原生不支持，引入需第三方依赖）。

## 8. 验收标准

1. `python main.py` 能启动，窗口 3 秒内出现，无异常输出。
2. 首次启动三个路径框已填好随程序附带的 `astyle\astyle.exe` 与 `.astylerc`，代码目录为空。
3. 选一个含 10 个以上 `.c/.h` 且有子目录的工程目录，点"开始风格化"：
   - 每个文件日志一行，状态正确（未格式化的显示 `OK`，已格式化的显示 `SKIP`）
   - 勾选备份时，被修改的文件生成 `xxx.c.orig` 且内容与格式化前一致；无变化的文件不留备份
   - 处理后的文件用 git diff 检查，改动与 Source Insight 单文件执行结果**逐字节一致**
4. 勾选"预览模式"：所有文件 mtime 与内容零变化；日志给出"将会修改 / 无需修改"；结束后临时目录被清理。
5. 处理 500 个文件期间可拖动窗口、可点"停止"（当前文件结束后停下），界面不"未响应"；界面日志超过 5000 行不卡顿。
6. 中文路径（如 `D:\工程\代码`）下正常处理，日志与窗口中文不乱码。
7. 关闭再打开，路径、勾选项、排除列表、历史目录、窗口位置全部恢复；把 settings.ini 中 geometry 改到屏幕外坐标后启动，窗口仍回到可见范围。
8. `logs\` 下生成当次日志文件，用记事本打开中文正常。
9. 把 `.c` 文件设为只读后处理，该文件显示 `FAIL`（附只读/被占用提示）、其余文件继续处理，结束后弹窗汇总失败数。
10. 自定义 exe/rc 路径后点"刷新"，先弹确认框；取消则路径保持不变。
11. 按 `docs/打包说明.md` 打包后，在未安装 Python 的机器上双击 `AstyleTool.exe`：无黑色控制台窗口，路径框默认值正确指向发布目录内的 `astyle\astyle.exe` 与 `.astylerc`，预览模式可完整跑通，`settings.ini` 与 `logs\` 生成在 exe 旁边。
